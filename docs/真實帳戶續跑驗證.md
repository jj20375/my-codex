# 真實帳戶續跑驗證

離線整合測試已驗證程式狀態轉移；以下流程用來確認實際訂閱、模型與配額行為。需要由擁有者登入自己的 Codex 帳戶。請在正常工作中觀察限額，不必為了測試刻意消耗額度。

## 登入與小任務

1. 開啟 `http://localhost:4327` → 帳戶與設定 → 登入 Codex 訂閱帳戶。
2. 在官方頁面輸入裝置碼並完成登入；介面應自動出現方案與額度。
3. 建立聊天，選取官方目錄中的模型與強度，送出：

```text
請在工作區建立 validation/hello.txt，內容是「Codex 工作區驗證成功」，
再讀回確認，回報結果。請不要操作工作區以外的檔案。
```

4. 檢查任務中心顯示完成、檔案面板可下載、Token 用量有官方紀錄。模型目錄不等於帳戶保證有權使用；若推論拒絕選取模型，改用帳戶實際可用模型。

## 持久專案範例

選取「專案實作」功能，再依真實需求修改並送出：

```text
請在工作區建立一個可離線使用的個人記帳網頁，支援新增、修改、刪除支出，
分類及月份篩選，並以本機儲存保存資料。請完成可執行程式、使用說明與必要驗證。

以 PROGRESS.md 記錄：需求、已完成步驟、驗證結果、尚未完成項目、下一步。
每完成一個可檢查的小步驟就更新進度；不要只提供計畫。
如果前一次執行被限額或程序中斷，先讀既有程式與 PROGRESS.md，
從尚未完成處繼續，避免重做已完成的外部操作。
```

這個範例可能在限額前就完成；任務大小與方案都會影響結果，無法保證一定觸發五小時限制。

## 實際遇到限額時

1. 任務中心應顯示「等待額度」，並保存原聊天、進度與下次確認時間。
2. 在 phpMyAdmin 的專用 DB 查看該筆 `jobs.id`、`sessionId`、`turnId`、`state`、`runAt`、`attempts`，以及 `sessions.threadId`。不要分享憑證 volume。
3. 可以執行 `docker compose restart api runner`；資料仍需保留，勿移除 volumes。
4. 官方恢復時刻到達後，系統重新查詢相關配額，再恢復原 thread、發起新 turn 接續。
5. 檢查同一個 job 的 attempts 增加、threadId 不變、原使用者訊息沒有重複、進度接續、任務最終完成。
6. 比較 session 的官方 token 記錄，確認快取輸入與推理輸出沒有再次加總。

如果配額恢復時間未知，系統每五分鐘重新確認。如果認證失效、模型存取被拒或無法確認上次派送結果，系統會顯示錯誤／待檢查，不會無限重播任務。

## 排程與附件

- 上傳一份實際 PDF、XLSX、PPTX、JPG/PNG，要求讀取可核對的內容。各格式需分別驗證，標頭通過不代表文件一定可解析。
- 聊天輸入「十分鐘後，整理這個專案目前的進度，建立單次排程」。進入排程面板確認具體時間及 prompt，再啟用。
- 確認前不得執行；確認後應只建立一個 job。主機必須醒著且 Docker 運作中。
